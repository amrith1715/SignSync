REASONS AND CORRECTIONS
1. Observed input geometry inconsistency: camera frames are 4:3; these uploads are square. MediaPipe x/z and y use different image dimensions, so the same pose can have different feature proportions. Uploads are now padded to 4:3 without stretching. This changed E from M (60.79%) to E (70.72%) before any model adaptation.
2. C -> B (92.18% baseline): the MLP decision boundary rejected the labeled C reference despite a detected hand. Geometry alone did not resolve it.
3. D -> X (69.57%): detected landmarks were assigned to X; geometry alone did not resolve it.
4. N -> NONE (45.97%): hand detected, but top model score was below the existing 60% acceptance threshold. Geometry alone did not resolve it.
5. O -> R (61.92%): geometry changed the wrong output to E; the classifier still did not identify O.
6. P -> Q (99.99%): highly confident wrong classification; a confidence threshold would not fix this.
7. U -> R (99.75%): highly confident confusion between these references; a confidence threshold would not fix this.
For items 2-7, the directly observed cause is the trained classifier assigning the extracted feature vectors to the wrong class (or rejecting them). Photo/training distribution differences and landmark errors are plausible contributing factors, not individually proven causes: no ground-truth 3D landmark annotations exist for these photographs.
